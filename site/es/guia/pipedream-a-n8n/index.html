Guía de migración · actualizada en octubre de 2026

Pipedream Workflows cierra el 31 de marzo de 2027. Así se mudan tus flujos a n8n.

Respuesta corta. Pipedream dejó de aceptar altas nuevas en Workflows el 30 de septiembre de 2026. Los flujos existentes siguen funcionando hasta el 31 de marzo de 2027, y todos los datos de Workflows, incluidas credenciales y tokens OAuth, se borran antes del 30 de abril de 2027. El export de Pipedream te da un archivo JSON por flujo, pero n8n no lo puede importar directamente: cada flujo hay que reconstruirlo o convertirlo.

Las fechas que importan

FechaQué pasa
30 sep 2026No hay altas ni suscripciones nuevas. Workflows queda en mantenimiento.
31 mar 2027Cierran Workflows y String. Las suscripciones terminan con reintegro proporcional.
30 abr 2027Se borran para siempre todos los datos de Workflows, incluidas credenciales y tokens OAuth.

Pipedream Connect (la API de Connect, los servidores MCP y el proxy de API) no se ve afectado. Solo cierran Workflows y String.

Qué trae el export y qué deja afuera

El export se hace de a un proyecto y genera un ZIP con un manifest.json y un archivo JSON por flujo. Cada archivo tiene sus disparadores, sus pasos (el código en los pasos de código, la clave y versión del componente en las acciones prearmadas) y los props que configuraste.

  • Borrado por seguridad: los valores secretos, las credenciales de las cuentas conectadas y los tokens OAuth (queda solo un authProvisionId, que funciona únicamente dentro de Pipedream).
  • No viene: variables de entorno, historial de eventos, data stores, archivos del File Store y el código de componentes privados de varios archivos.
  • Se saltea: los flujos que nunca se publicaron y lo que pase del límite de 500 flujos o 256 MB por export.

Así que antes de la fecha, bajá el contenido de tus data stores y copiá tus variables de entorno por separado. El export no los guarda.

Paso a paso

  1. Hacé un inventario. Listá cada flujo, marcá los importantes y anotá qué dispara a cada uno.
  2. Exportá cada proyecto. El ZIP se guarda en el File Store del proyecto; bajalo de ahí.
  3. Guardá lo que el export no trae. Bajá el contenido de los data stores y copiá las variables de entorno.
  4. Convertí. Reconstruí cada flujo en n8n a mano, o soltá el ZIP en MigrateFlows y recibí flujos de n8n más una lista de pendientes.
  5. Importá en n8n. Usá Import from file, o pegá el JSON del flujo en un lienzo vacío.
  6. Reconectá. Creá las credenciales y variables que necesita cada flujo.
  7. Probá con eventos reales. Corré cada flujo con un evento de muestra y compará el resultado con el de Pipedream.
  8. Hacé el cambio. Apuntá los webhooks y los emisores a las URLs nuevas de n8n. Si corrés las dos plataformas en paralelo un día, cuidá que el mismo evento no se procese dos veces.
  9. Apagá el flujo de Pipedream cuando n8n haya manejado tráfico real sin errores.

Lo que más se rompe

  • Paquetes npm. n8n Cloud no permite módulos npm externos en los nodos Code. n8n instalado por uno mismo los permite con NODE_FUNCTION_ALLOW_EXTERNAL.
  • Credenciales usadas en el código. El código que lee this.app.$auth necesita esos valores como variables de n8n, o pasar la llamada a un nodo HTTP Request con credencial.
  • Forma de los datos. Los nodos de apps de n8n no siempre devuelven los mismos campos que las acciones de Pipedream. Los pasos siguientes que leen campos específicos necesitan una revisión.
  • Duplicados y estado de sondeo. Las fuentes que sondean recuerdan lo que ya vieron. Reconstruí ese estado o la primera corrida en n8n puede reprocesar items viejos.
  • URLs de webhook. Cada webhook tiene una dirección nueva. Actualizala en cada servicio que manda eventos.
  • Husos horarios. Revisá el huso horario de cada programación después de mudarla.

Convertir automáticamente

MigrateFlows lee el ZIP del export de Pipedream o una carpeta de GitHub Sync y devuelve flujos de n8n listos para importar. Los pasos de código Node.js siguen funcionando con una pequeña capa de compatibilidad para steps, $.export, $.flow.exit, $.respond y axios. Las acciones prearmadas de servicios comunes pasan a nodos HTTP Request que usan tus propias credenciales de n8n, así devuelven los mismos datos que antes. Cada flujo viene con la lista de lo que queda por hacer a mano. Todo corre en tu navegador; tus archivos no se suben.

Preguntas

¿Puedo importar el export de Pipedream directamente en n8n?

No. Los formatos son distintos. Cada flujo hay que reconstruirlo o convertirlo antes.

¿Se vienen mis cuentas conectadas?

No. El export borra tokens y credenciales, así que conectás cada cuenta de nuevo en n8n.

¿También cierra Pipedream Connect?

No. Connect, sus servidores MCP y el proxy de API siguen funcionando.

¿Tengo que usar n8n?

No. Windmill, Trigger.dev, Make o código propio en una plataforma serverless también son opciones. n8n es una elección común porque tiene nodos de código, webhooks, programaciones y credenciales para cientos de servicios, y se puede instalar en un servidor propio.

Fuentes: documentación de Pipedream sobre el cierre de Workflows y sobre el export de flujos (pipedream.com/docs/workflows). MigrateFlows es independiente y no tiene relación con Pipedream, Workday ni n8n.
